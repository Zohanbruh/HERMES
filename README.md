# HERMES

**H**ealthcare cyb**E**r-**R**isk **M**odelling and **E**valuation via **S**imulation

A reproducible attack-graph and Monte Carlo framework for quantifying how much
each security control actually reduces cyber risk in a hospital network, and
what that reduction is worth.

> **All data in this repository is synthetic.** HERMES simulates a *reference*
> hospital architecture. It contains no patient data, no telemetry from any real
> provider, and no proprietary incident data. Parameters are calibrated to
> publicly reported incident characteristics; see [`docs/CALIBRATION.md`](docs/CALIBRATION.md).

---

## What this answers

| Question | Where |
|---|---|
| How far does an intrusion spread under a given control portfolio? | `scripts/02_main.py` |
| Which single control matters most, and does that change with context? | `scripts/03_ablation.py` |
| What drives the variance of the risk estimate? | `scripts/04_sensitivity.py` |
| Do controls stack additively? | `scripts/05_interaction.py` |
| How well can a SOC actually detect these intrusions? | `scripts/06_detection.py` |
| What is the best risk reduction per euro? | `scripts/07_frontier.py` |
| Does the model reproduce reported incidents? | `scripts/08_calibration.py` |

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
make test          # 64 unit tests, including an analytic Sobol benchmark
make all           # full pipeline: ~15 min on one core
```

Every figure and table in the accompanying manuscript is regenerated by
`make all`. Numbers quoted in the manuscript prose are emitted as LaTeX macros
into `paper/numbers.tex`, so the text cannot drift from the code.

## Model in one paragraph

The hospital is a 14-zone directed attack graph (`src/hermes/topology.py`), with
each edge labelled by a MITRE ATT&CK technique and carrying a base traversal
probability and a mean traversal time. A control portfolio is a coverage vector
in `[0,1]^7`; controls reduce edge probabilities multiplicatively
(`src/hermes/controls.py`). Each replication draws edge passability once
(percolation semantics), computes arrival times by Bellman–Ford, resolves
detection in closed form under a piecewise-exponential hazard, applies
containment, and converts held zones into outage hours, exposed records and
monetary loss (`src/hermes/simulator.py`).

Twenty thousand replications take roughly 0.2 s.

## Layout

```
src/hermes/
  topology.py     reference architecture and attack graph
  controls.py     control catalogue, efficacy matrix, portfolios, costs
  simulator.py    Monte Carlo kernel
  economics.py    ALE, loss exceedance, VaR/TVaR, ROSI, budget frontier
  statsx.py       bootstrap CIs, Cliff's delta, Holm correction, convergence
  sensitivity.py  Saltelli/Jansen Sobol indices, one-at-a-time tornado
  detection.py    synthetic SOC telemetry and detector benchmark
  viz.py          figures
scripts/          numbered experiments, each writing results/ and paper/
tests/            unit tests
docs/             calibration notes and the reproducibility checklist
```

## Reproducibility

* Every experiment is seeded. `SEEDS = (11, 23, 37, 53, 71)` in `scripts/_common.py`.
* Portfolio comparisons use **common random numbers**: the same seed drives every
  portfolio, so paired differences remove the shared campaign randomness.
* `make all` is deterministic. Re-running it overwrites `results/`, `figures/`
  and `paper/tables/` with byte-identical content on the same NumPy version.
* Exact versions are pinned in `requirements.txt`; `docs/REPRODUCIBILITY.md`
  records the environment used for the reported numbers.

## Known limitations

Stated plainly, because they bound what the results support:

1. **No real-world validation set exists.** The calibration in
   `scripts/08_calibration.py` is a face-validity check against published
   incident characteristics, not a goodness-of-fit test. Four of five targets
   are matched; the fifth is reported as a shortfall rather than tuned away.
2. **Control efficacy is expert-elicited**, not measured. The Sobol analysis
   shows how much of the conclusion depends on those priors.
3. **A single reference architecture.** Results transfer to estates that
   resemble it; small clinics and national clearing-houses do not.
4. **Adversaries are non-adaptive.** They do not re-plan when a control blocks a
   path, so the model is optimistic against a determined targeted attacker.
5. **ROSI scales linearly with the assumed campaign frequency**, which is the
   least well-grounded parameter in the model.
